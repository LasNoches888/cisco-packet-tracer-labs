# Лаба 01 — Базовая связность

## Цель
Связать две локальные сети через один маршрутизатор и проверить доступность хостов.

## Топология
```
[PC1]--[SW1]--Gi0/0--[R1]--Gi0/1--[SW2]--[PC2]
```
Оборудование: 1 × маршрутизатор (2911), 2 × коммутатор (2960), 2 × PC.
Кабели: PC–коммутатор и коммутатор–маршрутизатор — «copper straight-through».

## Адресация

| Устройство | Интерфейс | IP-адрес | Маска | Шлюз |
|------------|-----------|----------|-------|------|
| R1 | Gi0/0 | 192.168.1.1 | 255.255.255.0 | — |
| R1 | Gi0/1 | 192.168.2.1 | 255.255.255.0 | — |
| PC1 | NIC | 192.168.1.10 | 255.255.255.0 | 192.168.1.1 |
| PC2 | NIC | 192.168.2.10 | 255.255.255.0 | 192.168.2.1 |

## Настройка
Конфигурация маршрутизатора — [`R1.cfg`](R1.cfg). Коммутаторы работают с настройками по умолчанию.
На PC1 и PC2 задайте адрес, маску и шлюз во вкладке **Desktop → IP Configuration**.

## Проверка
```
R1# show ip interface brief
R1# show running-config | section interface
PC1> ping 192.168.1.1
PC1> ping 192.168.2.10
```
Ожидаемый результат: оба интерфейса R1 в состоянии `up/up`, ping с PC1 на PC2 успешен
(первый пакет может потеряться из-за ARP — это нормально).

## Для самостоятельной работы
1. Добавьте третью сеть `192.168.3.0/24` на новом интерфейсе R1 и ещё один PC.
2. Посмотрите ARP-таблицу: `show arp` на R1. Какие записи появились после ping?
3. Намеренно задайте PC2 неверный шлюз и найдите проблему по методике из
   [`docs/troubleshooting.md`](../../docs/troubleshooting.md).
