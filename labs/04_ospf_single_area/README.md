# Лаба 04 — OSPF, одна зона

## Цель
Настроить динамическую маршрутизацию OSPF (area 0) между тремя маршрутизаторами, соединёнными «треугольником»,
и убедиться, что при обрыве одного канала трафик идёт в обход.

## Топология
```
        192.168.1.0/24                192.168.2.0/24
             |                              |
           [R1]-------10.0.12.0/30--------[R2]
              \                            /
          10.0.13.0/30              10.0.23.0/30
                \                        /
                        [R3]
                          |
                   192.168.3.0/24
```
Оборудование: 3 × маршрутизатор 2911 (три гигабитных порта), по одному PC за каждым маршрутизатором.

## Адресация

| Маршрутизатор | Gi0/0 (LAN) | Gi0/1 | Gi0/2 | Router-ID |
|---------------|-------------|-------|-------|-----------|
| R1 | 192.168.1.1/24 | 10.0.12.1/30 → R2 | 10.0.13.1/30 → R3 | 1.1.1.1 |
| R2 | 192.168.2.1/24 | 10.0.12.2/30 → R1 | 10.0.23.1/30 → R3 | 2.2.2.2 |
| R3 | 192.168.3.1/24 | 10.0.23.2/30 → R2 | 10.0.13.2/30 → R1 | 3.3.3.3 |

PC1 / PC2 / PC3 получают первые адреса `.10` в своих сетях (шлюз — `.1`).

## Настройка
Конфиги: [`R1.cfg`](R1.cfg), [`R2.cfg`](R2.cfg), [`R3.cfg`](R3.cfg).

Что важно:
- `router-id` задан явно — не зависит от адресов интерфейсов и не меняется при их перенастройке;
- `passive-interface GigabitEthernet0/0` — в LAN нет соседей, hello-пакеты там не нужны;
- `network <сеть> <wildcard> area 0` — wildcard-маска (инверсия маски подсети): `/24` → `0.0.0.255`, `/30` → `0.0.0.3`.

## Проверка
```
R1# show ip ospf neighbor
R1# show ip route ospf
R1# show ip ospf interface brief
PC1> ping 192.168.3.10
PC1> tracert 192.168.3.10
```
Ожидаемый результат: у каждого маршрутизатора по два соседа в состоянии `FULL`, в таблице маршрутизации
записи `O` для всех удалённых сетей, трассировка PC1 → PC3 идёт напрямую через R1 → R3 (метрика 2 по сумме cost).

## Эксперимент: отказ канала
1. Запустите непрерывный ping с PC1 на PC3 (`ping -t 192.168.3.10`).
2. На R1 выполните `interface GigabitEthernet0/2` → `shutdown`.
3. Через несколько секунд OSPF сойдётся: `tracert` покажет путь через R2 (R1 → R2 → R3).
4. Верните линк (`no shutdown`) и убедитесь, что маршрут снова стал прямым.

## Для самостоятельной работы
1. Измените cost на интерфейсе (`ip ospf cost 50`) и заставьте трафик идти в обход прямого канала.
2. Добавьте `default-information originate` на R1 и статический маршрут по умолчанию — посмотрите маршрут `O*E2` на R2 и R3.
3. Включите аутентификацию OSPF (`ip ospf message-digest-key 1 md5 …`) на одном линке и найдите, как выглядит сбой соседства.
