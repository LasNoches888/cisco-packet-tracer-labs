# Лаба 02 — VLAN и trunk

## Цель
Разделить сеть на VLAN, связать два коммутатора trunk-линком и настроить управление через отдельный VLAN.

## Топология
```
 PC1 (VLAN10) --Fa0/1--[SW1]--Gi0/1 ======= Gi0/1--[SW2]--Fa0/1-- PC2 (VLAN10)
 PC3 (VLAN20) --Fa0/11-[SW1]                       [SW2]--Fa0/11- PC4 (VLAN20)
```
Оборудование: 2 × коммутатор 2960, 4 × PC. Между коммутаторами — Gi0/1 ↔ Gi0/1 (trunk).

## VLAN и адресация

| VLAN | Имя | Сеть | Назначение |
|------|-----|------|-----------|
| 10 | USERS | 192.168.10.0/24 | рабочие станции |
| 20 | SERVERS | 192.168.20.0/24 | серверы |
| 99 | MGMT | 192.168.99.0/24 | управление коммутаторами, native VLAN для trunk |

| Устройство | VLAN | IP-адрес |
|------------|------|----------|
| PC1 | 10 | 192.168.10.11/24 |
| PC2 | 10 | 192.168.10.12/24 |
| PC3 | 20 | 192.168.20.11/24 |
| PC4 | 20 | 192.168.20.12/24 |
| SW1 (SVI) | 99 | 192.168.99.11/24 |
| SW2 (SVI) | 99 | 192.168.99.12/24 |

## Настройка
Конфиги: [`SW1.cfg`](SW1.cfg), [`SW2.cfg`](SW2.cfg).

## Проверка
```
SW1# show vlan brief
SW1# show interfaces trunk
SW1# show interfaces GigabitEthernet0/1 switchport
PC1> ping 192.168.10.12      # успешно: один VLAN через trunk
PC1> ping 192.168.20.11      # неуспешно: разные VLAN, нет маршрутизации
SW1# ping 192.168.99.12      # успешно: управление в VLAN 99
```
Ожидаемый результат: VLAN 10/20/99 видны на обоих коммутаторах, в `show interfaces trunk`
разрешены VLAN 10, 20, 99, native VLAN = 99. Ping между VLAN 10 и VLAN 20 **не проходит** —
для этого нужен L3-узел, см. лабу 03.

## Для самостоятельной работы
1. Уберите VLAN 20 из `switchport trunk allowed vlan` и проверьте, что PC3 и PC4 перестали видеть друг друга.
2. Задайте разные native VLAN на двух концах trunk и найдите предупреждение
   `%CDP-4-NATIVE_VLAN_MISMATCH` в логе.
3. Перенесите неиспользуемые порты в отдельный VLAN 999 и выключите их (`shutdown`).
