# Лаба 05 — DHCP и NAT (PAT)

## Цель
Выдавать адреса клиентам локальной сети по DHCP с пограничного маршрутизатора и выпустить их «в интернет»
через NAT overload (PAT) с единственным внешним адресом.

## Топология
```
[PC1]--\
[PC2]---[SW1]--Gi0/0--[R1]--Gi0/1 ===== 203.0.113.0/30 ===== Gi0/0--[ISP]--Lo0 8.8.8.8
[PC3]--/
```
Оборудование: 2 × маршрутизатор 2911 (R1 — граница сети, ISP — «провайдер»), 1 × коммутатор 2960, 3 × PC.

## Адресация

| Устройство | Интерфейс | IP-адрес | Роль |
|------------|-----------|----------|------|
| R1 | Gi0/0 | 192.168.10.1/24 | `ip nat inside`, шлюз и DHCP-сервер LAN |
| R1 | Gi0/1 | 203.0.113.2/30 | `ip nat outside` |
| ISP | Gi0/0 | 203.0.113.1/30 | линк к R1 |
| ISP | Loopback0 | 8.8.8.8/32 | имитация внешнего узла в интернете |
| PC1–PC3 | NIC | DHCP | диапазон 192.168.10.11–192.168.10.254 |

Адреса `192.168.10.1–192.168.10.10` исключены из пула (`ip dhcp excluded-address`) — их можно выдавать вручную серверам и принтерам.

## Настройка
Конфиги: [`R1.cfg`](R1.cfg), [`ISP.cfg`](ISP.cfg).

На PC в **Desktop → IP Configuration** выберите **DHCP**.

Принцип работы NAT в этой лабе:
- ACL `1` описывает, чьи адреса можно транслировать (`192.168.10.0/24`);
- `ip nat inside source list 1 interface GigabitEthernet0/1 overload` подменяет адрес источника на внешний адрес R1
  и различает сессии по номерам портов;
- у ISP **нет** маршрута в `192.168.10.0/24`, поэтому без NAT ответы не вернутся — именно это и демонстрирует лаба.

## Проверка
```
PC1> ipconfig /all                     # адрес из пула, шлюз 192.168.10.1, DNS 8.8.8.8
R1# show ip dhcp binding
R1# show ip dhcp pool
PC1> ping 8.8.8.8                      # успешно через NAT
R1# show ip nat translations
R1# show ip nat statistics
```
Ожидаемый результат: в `show ip nat translations` — записи вида `icmp 203.0.113.2:N 192.168.10.11:N 8.8.8.8:N 8.8.8.8:N`
(внутренний локальный адрес транслируется во внешний адрес R1).

## Для самостоятельной работы
1. Отключите NAT (`no ip nat inside source list 1 …`) и убедитесь, что ping на 8.8.8.8 перестаёт работать. Почему?
2. Создайте статическую трансляцию (`ip nat inside source static tcp …`) для веб-сервера внутри LAN и откройте его снаружи.
3. Настройте второй пул DHCP для другой сети и DHCP-relay (`ip helper-address`) на соседнем маршрутизаторе.
